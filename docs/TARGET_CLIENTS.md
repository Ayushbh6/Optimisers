## Demo and dataset rules

Business decision relevant to these contacts → explicitly labelled example data or suitable real records → defensible evaluation → useful working demo.

**Direction updated 14 September 2026:** [DEMO_DATA_STRATEGY.md](DEMO_DATA_STRATEGY.md) governs the approved synthetic demonstration approach. Client showcase worthiness and a problem a real buyer could pay to solve are the core criteria. This does not authorise invented historical savings claims.

- Prioritise food/FMCG wholesale stock ordering and sales planning in the first demo design. Include manufacturing inventory/production opportunities for Perwanger in the first-two-demo portfolio assessment. One dataset need not serve all three firms.
- Keep all four gates: honest evidence, buyer value, established commercial practice, and a result worth showing a serious client.
- Verify source provenance, actual fields, time coverage and commercial reuse terms before selecting a dataset. Do not accept synthetic portfolio datasets as recorded operational evidence.
- Distinguish forecasting from optimisation. Better sales forecasts alone do not establish better purchasing decisions, avoided shortages or cash savings.
- Self-created, clearly labelled example data is now an approved resource. Public data is optional supporting evidence, not a prerequisite. Do not ask the user to buy data or obtain unavailable private records as the default solution.
- The original retail dataset was set aside for inadequate evidence, not because inventory ceased to be the target domain. Delivery-data suitability does not override client relevance.
- Synthetic-dataset implementation and its review were subsequently authorised and completed. See [DISTRIBUTOR_DATA_REVIEW.md](DISTRIBUTOR_DATA_REVIEW.md). Optimiser implementation remains a separate decision. Do not modify the locked Phase 2 plan.
- Keep project outputs inside this repository and retain only lean final evidence. The explicitly requested internal memory note is the exception.
